## 2. 功能需求 FR9

- FR9.1 卡片 CRUD：正面/反面文本，归属某方向（与日志同构）；在「复习」视图内管理。
- FR9.2 复习队列：到期复习卡（due ≤ now）优先；新卡按每日上限进入队列。**上限为后端常量 `REVIEW_NEW_LIMIT = 10`，前端不暴露、不加 settings 表**（Qoder 范围提醒采纳）。
- FR9.3 复习交互：显示正面 → 翻面 → 四级评分按钮「忘记 / 困难 / 良好 / 简单」。
- FR9.4 调度：FSRS-6 官方算法，`desired_retention=0.9`；评分后写回卡片状态与到期时间。
- FR9.5 复习记录：每次评分落 `review_logs`（评分、时间），为后续统计与参数优化留数据。
- FR9.6 复习统计：复习视图顶部计数——今日待复习 / 今日新卡 / 今日已完成 / 卡片总数。
- FR9.7 示例数据：`/api/demo` 附带 6 张嵌入式知识卡。**到期时间一律用 `datetime.now(timezone.utc) ± timedelta` 动态生成，禁止写死日期**（否则演示库随时间腐烂）。

## 3. 数据模型与迁移（首次结构变更）

```
cards(id INTEGER PK, direction_id INTEGER NOT NULL REFERENCES directions ON DELETE CASCADE,
      front TEXT NOT NULL, back TEXT NOT NULL DEFAULT '',
      fsrs TEXT NOT NULL,              -- 官方 Card.to_dict() 的 JSON 全量状态
      due TEXT NOT NULL,               -- 到期时间（UTC ISO 8601），供索引与排序
      created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')))

review_logs(id INTEGER PK, card_id INTEGER NOT NULL REFERENCES cards(id) ON DELETE CASCADE,
            rating INTEGER NOT NULL CHECK(rating IN (1,2,3,4)),
            reviewed_at TEXT NOT NULL) -- UTC ISO 8601，该表唯一时间列（不设 created_at，避免同表混两种时区）
```

- **迁移策略：additive-only**。SCHEMA 全部 `CREATE TABLE IF NOT EXISTS`，现有 `init_db()` 每次启动执行，v2.0 老库下次启动自动补建两张新表，无 ALTER、无停机。索引：`cards(direction_id, due)`、`review_logs(card_id, reviewed_at)`。
- **id 对齐决议（Qoder §三.1）**：插入时显式 `Card(card_id=表id)`，保证 `fsrs.card_id == cards.id`，全链路（review_logs、导出导入、调试）只用一套编号。
- **due 列格式决议（Qoder §三.2）**：`due 列 = Card.to_dict()['due'] 原样写入，禁止任何手工 strftime 拼接`；查询侧比较值（"现在"）也用同一来源生成——SQLite TEXT 字典序比较只在同构字符串下可靠。
- 卡片调度状态整体存 JSON，`due` 冗余成列只为队列查询；两者以 fsrs 库为唯一事实源。

## 4. FSRS 接入决策（按 Qoder 实测勘误修订）

- 依赖：`requirements.txt` 写 **`fsrs==6.3.2`**（本机安装的发行名就是 `fsrs`；`importlib.metadata.version('py-fsrs')` 查不到元数据，不要写 py-fsrs）。
- API 形态（v6.3.2 实测）：
  - `Scheduler(enable_fuzzing=False, desired_retention=0.9, ...)` —— **enable_fuzzing 是构造器参数**（默认 True，测试必须显式关闭）；
  - `sched.review_card(card, rating, review_datetime=None, review_duration=None) -> (Card, ReviewLog)` —— **实例方法，不是模块级函数**；
  - `review_datetime` **必须是 tz-aware UTC**：传 naive 直接 `ValueError`。代码一律 `datetime.now(timezone.utc)`，禁止 `datetime.utcnow()`（返回 naive，第一次调用就炸）；
  - `Card` v6 字段仅 `card_id / state / step / stability / difficulty / due / last_review`——**没有** v5 教程里的 `scheduled_days / elapsed_days / reps / lapses`；
  - 可锁进测试：`to_dict/from_dict` 与 `to_json/from_json` 往返一致；`Scheduler` 亦有 `to_dict/from_dict`；`enable_fuzzing=False` 时同输入两次结果完全相等。
- 断言基准（`Scheduler(enable_fuzzing=False)`，`review_datetime=2026-09-19T12:00:00+00:00`，新卡）：
  Good → `state=1, step=1, stability=2.3065, difficulty=2.1181, due=2026-09-19T12:10:00+00:00`；再 Good → `state=2, due=+2 天`；再 Again → `state=3, stability=0.608`。
- 评分映射：忘记=Rating.Again、困难=Rating.Hard、良好=Rating.Good、简单=Rating.Easy。
- 时间统一 **UTC 存储**、前端转本地显示。

## 5. API 变更（新增）与备份兼容

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/directions/{id}/cards | 卡片列表（含 state/due） |
| POST | /api/directions/{id}/cards | 新建 `{front, back?}` |
| PATCH/DELETE | /api/cards/{id} | 编辑 / 删除 |
| GET | /api/directions/{id}/review/queue | 今日队列：到期卡 + 新卡（按上限截取）+ 计数 |
| POST | /api/cards/{id}/review | `{rating: 1..4}` → FSRS 调度、写回、落 review_logs |

- cards 纳入导出/导入备份，`_BACKUP_SPEC` 加行，**导出永远写当前版本号**。
- **备份版本兼容矩阵（Qoder §二，最要紧）**：现有 `_valid_backup` 先查版本再查表键，v1 备份没有 cards 键会被"缺少 cards 数据"挡掉，§9.4 的验收必红。显式实现：

  | 库 \ 备份 | v1 备份 | v2 备份 |
  |---|---|---|
  | **v2.0 库** | OK | 拒绝，提示升级 |
  | **v3 库** | OK（cards/review_logs 按 `[]` 处理） | OK（两张表必须存在） |

  实现：`ACCEPTED_VERSIONS = {1, 2}`；version 1 时 cards/review_logs 缺失按空表放行；version 2 时两张表必须存在且走 spec 校验；**版本高于本程序支持时文案明说**：「备份版本 X 高于本程序支持的 Y，请升级程序后再导入」，不再笼统报"不是有效的备份"。
- **详情页徽标防 N+1 回流（Qoder §五）**：今日待复习数由方向列表接口**一次 `GROUP BY` 聚合**（`SELECT direction_id, COUNT(*) FROM cards WHERE due <= ? GROUP BY direction_id`，常数次查询），不在详情页逐方向查。

## 9. 测试与验收（按 Qoder §四修正）

1. **调度行为**：断言必须**显式传 `review_datetime`**（无参 `Card()` 的 due 是"现在"，不传就随运行时间漂移）。间隔单调断言限定在**进入 `State.Review` 之后**：先评 Good 两次把卡推进 Review 态（实测第一次 Good 仅 +10 分钟，第二次 +2 天），此后连续 Good 的 due 间隔单调不减。基线值见 §4。
2. **队列语义**：新卡上限生效（12 张卡、上限 10 → 队列 10）；到期卡评分后移出当日队列；明日到期卡不出现在今日队列。
3. **迁移（自包含）**：tests 内联一份 **v2.0 四表 SCHEMA 常量**，建库 → 塞旧数据 → 调当前 `init_db()` → 断言两张新表出现且旧数据完整可查。不依赖 git 历史文件。
4. **备份兼容**：按 §5 矩阵四行逐条断言（v2库×v1备份 / v3库×v1备份 / v3库×v2备份 / 高版本拒绝文案）。
5. **列表口径**（TD2 防回归）：见 §7。
6. **浏览器**：建卡 → 复习完整流程 → 计数变化；卡片增删改即时反映。
7. 原有 96（临时库）/ 54（真实服务）门禁回归全绿；cards 相关新断言按 docs/05 §3 补入同一测试文件。
