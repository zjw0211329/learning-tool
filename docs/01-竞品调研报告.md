# 01 竞品调研报告 —— 个人学习记录/追踪类软件

> 项目代号：study tools（大学四年个人学习管理软件）
> 阶段：需求分析前期 · 竞品调研
> 日期：2026-09-19
> 调研方法：GitHub Search API 关键词检索（中英文多组关键词）+ 对已知项目定向核实（星标数与活跃度以查询当日为准）

## 一、调研结论（TL;DR）

「按学习方向（如嵌入式）一步步记录个人学习过程」这个细分需求，**目前没有一个成熟的一体化开源项目**。

现有生态呈"三件套分离"格局：

1. **路线图内容**（学什么）—— 超级热门，纯内容/交互图表，不管进度记录；
2. **知识记录**（记什么）—— 笔记软件高度成熟，但不以"学习方向/阶段/任务"为主线；
3. **进度与习惯**（怎么坚持）—— 打卡、番茄钟、待办工具很多，但与学习内容无关。

而最接近"一体化"的尝试（路线图导入 + 进度跟踪 + 学习日志）全部是 1~4 星的个人/学生项目，成熟度极低。**这既是需求真实存在的信号，也是差异化空间。**

## 三、对本项目的启示

1. **不做内容**：学习路线/课程内容直接引用（如 roadmap.sh、cs-self-learning），本项目聚焦"记录与推进"这一层。
2. **主线是"方向 → 阶段 → 任务 → 日志"**：以一个学习方向（如"嵌入式"）为根，向下拆阶段、任务，每个任务挂学习日志（TIL 式短记录）—— 这是所有竞品都没有做顺的核心结构。
3. **轻记录重回顾**：TIL 模式（每天一条、Markdown、按时间线回看）比"完整笔记软件"更贴合"一步步记录"的诉求；笔记软件可做导出对接而不是重新造。
4. **坚持机制可选**：打卡/番茄钟/复习卡片作为可选模块，第一期不追求全有。
5. **数据本地优先**：思源、AppFlowy、super-productivity 的成功都验证了"数据在自己手里"是这类工具的核心信任点。
6. **可借鉴的具体设计**：
   - developer-roadmap 的路线图节点数据结构（节点/连线/分组）
   - beaverhabits 的极简打卡 UI
   - FSRS 的复习调度算法（若做复习模块）
   - TIL 的 `YYYY-MM-DD-主题.md` 命名与索引约定
