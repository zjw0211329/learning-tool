## 2. FR10 阶段任务列表折叠

- 阶段标题行左侧加折叠开关（▸ 折叠 / ▾ 展开）；折叠时收起任务列表与添加任务表单，
  保留阶段名 + 进度条 + 进度 % + `done/total` 计数摘要——一行就是一个阶段的全貌。
- 展开为默认态；折叠状态按 phase id 记入 localStorage（`st_collapsed_phases`），
  刷新页面、切换视图回来、增删任务后仍保持（roadmap 每次全量重建，状态不能挂在
  phase 对象上，必须独立于 `detail.phases` 生命周期）。
- localStorage 读取必须 try/catch：损坏 JSON 一律回退为「全部展开」，不弹错；**写入侧同样
  包 try/catch**（隐私模式/配额满时降级为仅本次会话有效，不冒未捕获错误——Qoder nit）。
- 折叠记录的生命周期：阶段删除后残留记录无害（正常操作 phase id 不复用）不做清理；
  **导入备份是例外**——整库替换会重新分配全部 id，残留记录将张冠李戴（Qoder 实测复现：
  折叠阶段 id 72 → 导入后 72 属于另一阶段 → 该阶段莫名其妙处于折叠态，即 docs/05 §3.6
  的共享状态不对称）。因此 `doImport` 成功分支必须复位折叠表并清 localStorage。

## 3. FR11 周时长柱状图时间单位

- 现状缺陷：Y 轴只有轴顶小字「分钟」，tooltip 是裸数字（如 `540`），用户看不出
  是分钟还是小时。
- 方案：**整图统一小时口径**——series 数据分钟转小时（保留 1 位小数），Y 轴
  name 改「小时」，tooltip 显示人性化时长（复用 `fmtMinutes`，如「9 小时 30 分」）。
- 热力图 tooltip 顺带统一：原「学习 X 分钟」改「学习 X 小时 Y 分」（fmtMinutes），
  全局时长文案一个口径。
- 不动 ECharts 其他配置（颜色/网格/交互均维持现状，简约约束）。

## 7. FR12 输入健壮性收紧（用户审查轮，2026-09-22）

修复清单与三项设计决策（契约面判定：全部为既有接口的校验收紧/行为修正，
零 API 形状变更、零数据模型/依赖/备份格式改动，按 docs/05 §4 属计划与代码
同轮交审的滚动轮）：

1. **导入校验 500→400**：`version` 为数组/对象时 set 成员测试直接 TypeError；
   `True==1`、`2.0==2` 被 `in` 的相等语义错误放行。修：`_is_int` 严格先行
   （bool 已排除）。外键字段（direction_id/phase_id/card_id）补进 `_BACKUP_SPEC`
   声明表——原来只在跨表外键段做 set 成员测试，不可哈希值直接 500；进声明表后
   逐表先拒（400 带中文标签），符合「新增可导入字段加一行」的表驱动哲学。
2. **PATCH 严格部分更新**（决策：字段在则校验并更新、不在则保留原值；两者皆缺
   → 400「至少提供一个字段」）。原实现 name 必填 + 全字段 UPDATE：只提交 name
   静默清空描述/目标、只提交描述直接 400。与 `_text_field` 的「可选空串合法」
   语义对齐：显式提交空串 = 清空，字段缺失 = 不动。前端总是全量提交，不受影响。
3. **move phase_id 严格整数**：`int()` 静默转换 1.5/true/"1" → 一律 400，
   与 minutes 严格口径一致（V3.1 决议：禁止静默截断）。
4. **未来日期日志拒绝**（决策：POST 与 PATCH 同口径拒绝 `date > 今天`）。
   日志语义是「已发生的学习」，9999-12-31 曾被接受并污染累计时长/活跃天数/
   热力图。demo 数据全为过去日期，不受影响。存量脏数据经 Qoder 只读核查真实库
   （2026-09-22）确认不存在（1 方向 / 25 任务 / 1 条日志 / 0 卡片，无未来日期、
   无审查残留），无需任何清理。
   - **明确例外：`/api/import` 不拦未来日期日志**（2026-09-22 用户裁决「保持放行」，
     Qoder 复核后落档）。Qoder 审查实测该入口确实放得进 9999-12-31 并计入活跃天数
     与热力图，属 docs/05 §3.6「入口对称性」形态；但此处**有意保持不对称**：导入是
     数据自救/迁移通道，一旦同样设限，「当年带着脏日期导出的旧备份」将永远导不回来
     （与「坏 fsrs 行原样带出、导出永远可用」同一条哲学）。导入仍保留格式级严格
     （`_is_iso_date` 一律拒非法形状），只在内容级政策上松一档；脏日志进来后可以在
     「最近记录」删除，且 /stats 对非法日期已有 200 兜底不会打死页面。
     该例外同时写进 `_valid_backup` 的 docstring，防止将来被「顺手补齐」。
5. **评分接口服务端强制新卡上限**（决策：只限「新卡首评」，口径与队列同一函数
   `_introduced_new_today`——抽公共函数防两入口漂移）。新卡（last_review 为空）
   首评时若本方向今日已引入 ≥ REVIEW_NEW_LIMIT → 400；学习步骤内的再次评分与
   到期卡评分不受限，不伤 FSRS 正常流程。**上限按方向各计**（追认 FR9.2 澄清：
   N 个方向一天共可引入 10N 张新卡，多方向并行学习不互相挤占配额）。
   附带修复（Qoder 复验发现）：rateCard 评分被拒时也刷新队列——否则并发标签页
   把配额用光后，屏幕上会留着一张永远评不动的旧卡。
6. **前端 doImport 防御**：JSON.parse 合法但非对象（null/数字/字符串/数组）先挡；
   removeItem 包 try/catch（用户要求，成本一行）。
7. **测试脚本 GBK 兼容**：stdout reconfigure UTF-8 + errors=replace，
   Windows 默认 GBK 控制台不再 UnicodeEncodeError 崩整轮。
8. **favicon.ico**：新路由 serve assets/studytool.ico（单一事实源），消除 404。
