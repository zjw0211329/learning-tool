# 03 概要设计

> 前置文档：《02 需求规格说明书》
> 版本：v1.0（MVP） · 日期：2026-09-19

## 1. 技术选型（推荐结论及理由）

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **Python 3 + Flask 3**（本机已装 3.1.3） | 零安装成本、代码直观易读；Flask 足以支撑单机个人应用；自带 debug 工具链 |
| 数据库 | **SQLite**（标准库 sqlite3） | 单文件、零配置、备份即复制；个人本地应用的最优解 |
| 前端 | **Vue 3（global build，本地 vendor）**，免构建 | 无需 Node 工具链即可运行与修改；响应式天然适合"勾任务→进度即时更新" |
| 图表 | **ECharts 5（本地 vendor）** | 日历热力图、条形图开箱即用，中文文档完善 |
| 交付 | `python app/main.py` 一键启动 + run.bat/run.sh | 满足 NFR3 可移植 |

> 说明：Node/npm 本机可用，但 MVP 刻意不走 Vite 构建链——以"克隆即跑"优先，构建链留到需要工程化时（V2）再引入。

## 3. 数据模型（SQLite DDL 摘要）

```
directions(id INTEGER PK, name TEXT NOT NULL, description TEXT DEFAULT '',
           created_at TEXT DEFAULT now)
phases(id INTEGER PK, direction_id INTEGER NOT NULL REFERENCES directions ON DELETE CASCADE,
       name TEXT NOT NULL, goal TEXT DEFAULT '', sort_order INTEGER DEFAULT 0, created_at TEXT)
tasks(id INTEGER PK, phase_id INTEGER NOT NULL REFERENCES phases ON DELETE CASCADE,
      title TEXT NOT NULL, note TEXT DEFAULT '',
      status TEXT NOT NULL DEFAULT 'todo' CHECK(status IN ('todo','doing','done','skipped')),
      sort_order INTEGER DEFAULT 0, created_at TEXT, done_at TEXT NULL)
logs(id INTEGER PK, direction_id INTEGER NOT NULL REFERENCES directions ON DELETE CASCADE,
     date TEXT NOT NULL,              -- YYYY-MM-DD
     minutes INTEGER DEFAULT 0,       -- 当次学习分钟数
     content TEXT DEFAULT '', created_at TEXT)
```

- 级联删除依赖 SQLite `PRAGMA foreign_keys = ON`（连接级开启）。
- 索引：`logs(direction_id, date)`、`tasks(phase_id)`。

## 4. API 设计（REST，/api 前缀，JSON）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/directions | 方向列表（含任务统计与进度汇总） |
| POST | /api/directions | 新建方向 `{name, description?}` |
| PATCH | /api/directions/{id} | 改名/改描述 |
| DELETE | /api/directions/{id} | 删除方向（级联） |
| GET | /api/directions/{id}/roadmap | 方向 + 阶段树 + 任务 |
| POST | /api/directions/{id}/phases | 新建阶段 `{name, goal?}` |
| PATCH/DELETE | /api/phases/{id} | 编辑/删除阶段 |
| POST | /api/phases/{id}/tasks | 新建任务 `{title, note?}` |
| PATCH | /api/tasks/{id} | `{status?}` / `{title?,note?}`；置 done 时写 done_at |
| DELETE | /api/tasks/{id} | 删除任务 |
| GET | /api/directions/{id}/logs?from&to | 日志查询（倒序） |
| POST | /api/directions/{id}/logs | 新增日志 `{date, minutes?, content?}` |
| PATCH/DELETE | /api/logs/{id} | 编辑/删除日志 |
| GET | /api/directions/{id}/stats | 汇总：任务统计、阶段进度、热力图（近365天）、周时长（近12周）、streak、累计分钟 |
| GET | /api/directions/{id}/review?date=YYYY-MM-DD | 周报：该周每日日志、完成任务、合计时长（周一为周首） |
| POST | /api/demo | 载入「嵌入式」示例数据（幂等：仅当无任何方向时生效） |

错误约定：参数缺失/非法 → 400 `{"error": "..."}`；资源不存在 → 404；成功写操作返回新资源或 `{"ok": true}`。

## 5. 前端视图设计（单页，顶部三个 Tab）

1. **总览**：方向卡片网格（名称、进度条、任务 x/y、累计时长、连续天数）；新建方向表单；空状态 → 引导 + 「载入示例数据」按钮。
2. **方向详情**（点卡片进入）：
   - 左栏（主）：阶段卡片列表 → 每阶段内任务清单（复选框循环切换 todo→doing→done；skipped 经下拉切换）；各阶段底部「+ 添加任务」；顶部「+ 添加阶段」；每项有编辑/删除小按钮。
   - 右栏（侧）：今日速记表单（日期默认今天、分钟数、内容）+ 最近日志列表（倒序，可删）。
3. **统计回顾**（选方向）：顶部指标卡（累计时长/活跃天数/连续天数/完成率）；ECharts 日历热力图（近一年）+ 周时长条形图（近12周）+ 阶段进度条；下方周报区（周选择器 → 每日时间线 + 完成任务清单）。

视觉基调：白底卡片、圆角、留白；主色靛蓝 `#4f46e5`；状态色：done 绿 / doing 琥珀 / todo 灰 / skipped 删除线灰。

## 6. 关键算法

- **进度**：`done / (total - skipped)`；分母为 0 时进度视为 0%。
- **streak（连续记录天数）**：取该方向有日志（或分钟>0）的日期集合，从今天开始向前数；今天未记录则从昨天起数，连续计数中断即停。
- **热力图数据**：`SELECT date, SUM(minutes) FROM logs WHERE direction_id=? AND date >= today-364 GROUP BY date`。
- **周报区间**：给定日期所属周一 ~ 周日；完成任务按 `done_at` 落在该区间。

## 7. 测试与验证计划（对应阶段：测试）

1. API 冒烟：curl 依次执行建方向→建阶段→建任务→改状态→记日志→取 stats/review，核对 JSON 数值。
2. 持久化：重启服务后数据仍在。
3. GUI 冒烟：浏览器打开三视图，执行勾选任务、添加日志、查看热力图。
4. 验收标准对照《02》第 6 节逐条核对。
