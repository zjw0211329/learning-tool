# 04 V2 迭代计划（v2.0）

> 前置文档：《02 需求规格说明书》《03 概要设计》
> 版本：v2.1（含 Qoder 审查结论落地） · 日期：2026-09-19
> 本文档扩展 SRS 的功能需求编号（FR6 起），数据库结构不变（V2 全部复用既有四张表）。

## 1. 迭代目标

补全 MVP 砍掉的三项高价值能力，均不引入新技术依赖：

| 编号 | 功能 | 说明 |
|---|---|---|
| FR6 | 任务与阶段排序、跨阶段移动 | 补全路线图体验：阶段/任务支持上移下移；任务可移动到其他阶段 |
| FR7 | 数据导出 / 导入（JSON） | 数据安全闭环：整库导出为 JSON 备份；导入=整库替换（需确认）。**本 FR 取代《02》FR5.3**（FR5.3 仅写了导出，导入未实现，由本 FR 一并完成） |
| FR8 | 番茄钟 | 25 分钟专注 + 5 分钟休息；专注结束自动把 25 分钟记入当日学习日志 |

## 2. 功能需求

### FR6 排序与移动
- FR6.1 阶段、任务支持「上移 / 下移」，顺序按 (sort_order, id) 稳定排序。**边界行为定为 200 空操作**（第一个再点上移什么都不发生，前端不禁用按钮，接口幂等）。
- FR6.2 任务可移动到同方向的其他阶段（移动后排在目标阶段末尾）。**服务端强制校验目标阶段与任务原阶段属于同一 direction**（前端下拉限制只是体验，接口是防线）。
- FR6.3 任务状态圆点四态循环：未开始 → 进行中 → 已完成 → 跳过 → 未开始（替代原独立「跳过」按钮，减少行内按钮拥挤）。

### FR7 数据导出 / 导入
- FR7.1 导出：`/api/export` 返回四张表全量 JSON（含 `app`/`version`/`exported_at` 元信息）；`?download=1` 时以附件下载。
- FR7.2 导入：`/api/import` 接受导出格式的 JSON，**整库替换**（清空后写入），单事务完成，失败自动回滚；结构或字段非法返回 400。
- FR7.3 前端「数据管理」卡片（总览页底部）：导出下载按钮 + 文件选择导入（导入前二次确认）。
- FR7.4 **关于 sqlite_sequence（Qoder 审查项）**：导入写入显式 id 后无需手动重置序列——已实证 SQLite 的 AUTOINCREMENT 在显式 rowid 插入时会自动把 sqlite_sequence 推进到 max(id)（导入 id=7 后无 id 新建得到 8），不存在撞号。以 `tests/api_smoke.py` [7] 的「导入后新建方向 id 必须大于备份最大 id」断言持续守护。

### FR8 番茄钟
- FR8.1 方向详情页侧栏顶部提供番茄钟卡片：默认 25 分钟专注 / 5 分钟休息，可开始/暂停/重置。
- FR8.2 专注结束时：自动向**开始专注时所绑定的方向**追加一条日志（minutes=25，content="🍅 番茄钟专注"），toast 提示，随后自动切换到休息倒计时（不自动开始）。
- FR8.3 **计时实现必须用 endTime 绝对时间戳反算剩余秒数**（Qoder 审查项）：`setInterval` 在后台标签页被节流到约 1 次/分钟，逐秒减 1 会严重偏慢；每次 tick 以 `Math.round((endAt - Date.now()) / 1000)` 反算，节流只影响提醒时机、不影响计时正确性。刷新页面后计时器重置（纯前端实现，接受该限制）。
- FR8.4 显示本次会话已完成番茄数（页面内存计数，不入库）。

## 3. 统计口径决策（Qoder 审查缺陷 B）

方向级与阶段级的 `total` **统一为不含已跳过（skipped）任务**，`progress = done / total`。
选择该方案而非「total 含 skipped + 另给 effective_total」，理由：前端所有「x/y」展示位（总览卡片、方向详情 chips、阶段头、统计页阶段进度）含义一致，无需多处区分两个字段；已跳过任务属于"退出计划"，不计入任何展示分母。该口径已写入 `direction_progress()` 的 docstring，并由 `tests/api_smoke.py` [2] 的断言守护。

## 4. 明确不做（V2 范围外 → V3 候选）

复习卡片（FSRS 间隔重复）· 移动端深度适配 · AI 生成路线图 · Vite 构建链 · 任务拖拽（按钮排序已满足）· 方向列表 N+1 查询优化（个人数据量小，暂不构成瓶颈，V3 顺带处理）

## 5. API 变更（新增）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/phases/{id}/reorder | `{direction: "up"\|"down"}` 与相邻阶段交换 sort_order；边界为 200 空操作 |
| POST | /api/tasks/{id}/reorder | `{direction}` 与同阶段相邻任务交换；边界为 200 空操作 |
| POST | /api/tasks/{id}/move | `{phase_id}` 移动任务到目标阶段末尾（仅限同方向，否则 400） |
| GET | /api/export[?download=1] | 全量导出 JSON |
| POST | /api/import | 整库替换导入 |
| GET | /api/directions/{id}/logs?limit=N | 新增 limit 参数（"最近记录"侧栏用 30），不带 limit 仍返回全量 |

## 6. 验收标准

1. 同阶段内上移/下移后刷新页面顺序保持；移动任务到另一阶段后目标阶段进度与原阶段进度即时联动；跨方向移动被 400 拒绝。
2. 导出 JSON → 新建一个方向 → 导入该 JSON → 新方向消失、数据与导出时一致；损坏的 JSON 导入返回 400 且原数据不变；导入后新建方向的 id 大于备份中的最大 id。
3. 番茄钟走完一整个专注周期（测试中把剩余秒数置小）→ 自动生成一条 25 分钟日志、今日速记列表可见、标签标题恢复正常；专注期间切换方向，日志仍落在开始时的方向。
4. 统计回顾 → 总览 → 再进统计回顾，两张图表正常渲染（缺陷 A 回归点）。
5. 原 MVP 全部验收标准（见《02》第 6 节）回归通过。
