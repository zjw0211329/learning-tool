# 04 V2 迭代计划（v2.0）

> 前置文档：《02 需求规格说明书》《03 概要设计》
> 版本：v2.0 · 日期：2026-09-19
> 本文档扩展 SRS 的功能需求编号（FR6 起），数据库结构不变（V2 全部复用既有四张表）。

## 1. 迭代目标

补全 MVP 砍掉的三项高价值能力，均不引入新技术依赖：

| 编号 | 功能 | 说明 |
|---|---|---|
| FR6 | 任务与阶段排序、跨阶段移动 | 补全路线图体验：阶段/任务支持上移下移；任务可移动到其他阶段 |
| FR7 | 数据导出 / 导入（JSON） | 数据安全闭环：整库导出为 JSON 备份；导入=整库替换（需确认） |
| FR8 | 番茄钟 | 25 分钟专注 + 5 分钟休息；专注结束自动把 25 分钟记入当日学习日志 |

## 2. 功能需求

### FR6 排序与移动
- FR6.1 阶段、任务支持「上移 / 下移」，顺序按 (sort_order, id) 稳定排序。
- FR6.2 任务可移动到同方向的其他阶段（移动后排在目标阶段末尾）。
- FR6.3 任务状态圆点改为四态循环：未开始 → 进行中 → 已完成 → 跳过 → 未开始（替代原独立「跳过」按钮，减少行内按钮拥挤）。

### FR7 数据导出 / 导入
- FR7.1 导出：`/api/export` 返回四张表全量 JSON（含 `app`/`version`/`exported_at` 元信息）；`?download=1` 时以附件下载。
- FR7.2 导入：`/api/import` 接受导出格式的 JSON，**整库替换**（清空后写入），单事务完成，失败自动回滚；结构或字段非法返回 400。
- FR7.3 前端「数据管理」卡片（总览页底部）：导出下载按钮 + 文件选择导入（导入前二次确认）。

### FR8 番茄钟
- FR8.1 方向详情页侧栏顶部提供番茄钟卡片：默认 25 分钟专注 / 5 分钟休息，可开始/暂停/重置。
- FR8.2 专注结束时：自动向当前方向追加一条日志（minutes=25，content="🍅 番茄钟专注"），提示音效可无（MVP 用 toast 提示），随后自动切换到休息倒计时（不自动开始）。
- FR8.3 计时进行中在浏览器标签标题显示剩余时间；页面刷新后计时器重置（纯前端实现，接受该限制）。
- FR8.4 显示本次会话已完成番茄数（页面内存计数，不入库）。

## 3. 明确不做（V2 范围外 → V3 候选）

复习卡片（FSRS 间隔重复）· 移动端深度适配 · AI 生成路线图 · Vite 构建链 · 任务拖拽（按钮排序已满足）

## 4. API 变更（新增）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/phases/{id}/reorder | `{direction: "up"\|"down"}` 与相邻阶段交换 sort_order |
| POST | /api/tasks/{id}/reorder | `{direction}` 与同阶段相邻任务交换 |
| POST | /api/tasks/{id}/move | `{phase_id}` 移动任务到目标阶段末尾 |
| GET | /api/export[?download=1] | 全量导出 JSON |
| POST | /api/import | 整库替换导入 |

## 5. 验收标准

1. 同阶段内上移/下移后刷新页面顺序保持；移动任务到另一阶段后目标阶段进度与原阶段进度即时联动。
2. 导出 JSON → 新建一个方向 → 导入该 JSON → 新方向消失、数据与导出时一致；损坏的 JSON 导入返回 400 且原数据不变。
3. 番茄钟走完一整个专注周期（测试中用暴露的调试句柄把剩余秒数置 1）→ 自动生成一条 25 分钟日志、今日速记列表可见、标签标题恢复正常。
4. 原 MVP 全部验收标准（见《02》第 6 节）回归通过。
